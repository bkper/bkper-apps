# System One discovery trial

Can a System One decision model make Bookbot's discovery decision: given a bank line on a known bank Account, which Account of the Book is the other side, or none? This trial asks Jev (TypeSafe) and Clef (Cloudflare) the same two questions through the Bkper AI gateway's `POST /v1/systemone` (Open System One 2026-11-07). It changes nothing in Bookbot.

## Method

- 38 synthetic cases (`cases.ts`) in three invented Books: a US software company (English), a Brazilian bakery (Portuguese Accounts and lines) and a personal Book (English Accounts, Portuguese bank lines). 31 cases have an expected Account and 7 have none that fits. Tags: clear 21, noisy 19, multilingual 19, ambiguous 8, none_fits 7; a case can have several tags.
- One request per case and model (`request.ts`). The state is the bank line: bank Account, direction, amount and description. Two questions: `fits` (`noul`: is one of the Accounts the other side?) and `account` (`choice` over every Account of the Book except the bank Account, each described by type and group only).
- Decision rule: suggest the chosen Account when `fits` ≥ 0.5, otherwise no suggestion. A wrong suggestion is a wrong Account, or any suggestion when none fits; a missed suggestion is no suggestion when an Account fits.
- 76 live calls (38 per model, sequential, no retries, no errors) on the production gateway on 2026-11-08, recorded in `recordings.json`. An earlier run on the dev gateway on 2026-11-07 reached the same conclusions. Clef returned identical answers in both runs. Jev, at the same version (1.13.0), changed 28 of 38 answers slightly, and two cases crossed a threshold: on the United Airlines line `fits` fell from 0.50 to 0.36, and on GitHub the choice confidence fell from 0.91 to 0.86. Latency is wall time measured from the caller, including the network to the gateway. Every request body was distinct, so the gateway's response cache was never hit. Cost is usage times the gateway catalog price at recording time, which includes Bkper's markup: Jev 63 and Clef 360 nano USD per input token, output free.

## Recommendation

**Jev, if Bookbot adopts a System One model; keep the current discovery as the primary path.**

Jev against Clef, on these numbers:

- Jev is more accurate: choice accuracy 96.8% against 90.3%, and end-to-end decision accuracy 89.5% against 78.9%, with 1 wrong suggestion against 3 and 3 missed against 5. Clef did better only on the ambiguous tag (7/8 against 6/8), one case apart.
- Jev's confidence is usable as a gate. With `fits` ≥ 0.5 and choice confidence ≥ 0.9, Jev made 25 suggestions, all correct, covering 80.6% of the cases with an Account. Clef's confidence is compressed (highest 0.94): at 0.9 it suggests only 4 times, and at 0.7 it covers 61.3% with one wrong suggestion. Jev's `fits` probability is also better calibrated (Brier 0.091 against 0.111).
- Jev is faster and cheaper: 220 ms median and 314 ms p95 against 537 ms and 1,040 ms, and about $0.000047 per call against $0.000226, about 4.8 times less.

Against the current discovery, these numbers do not justify a replacement. Current discovery reuses the Account the Book already used for similar posted transactions: Gemini Flash-Lite extracts description parts and a history search picks the most frequent Accounts. That follows each Book's own conventions, which a model that sees only Account names, types and groups cannot know; this trial has no history to compare it against. One Flash-Lite extraction costs roughly $0.0003, an unmeasured estimate (about 450 input tokens from the prompt length at four characters per token, plus a few output tokens, at the catalog price), so a Jev call would add about a sixth of that.

Where Jev fits is the case current discovery cannot handle: `no_match`, such as a first transaction with a new merchant or a Book without history. A next step, which needs separate approval, is a Jev fallback after `no_match` that suggests only when `fits` ≥ 0.5 and confidence ≥ 0.9, with the suggested Account validated against the target Book as today, and measured on real, consented `no_match` drafts before it ships.

Limits: 38 synthetic cases written and labelled by one author, one run per model and small counts (25 of 25 correct still has a 95% lower bound near 86%). Some labels are debatable; both models put Peloton under Software Subscriptions with confidence below 0.9. Real Books can have hundreds of Accounts, more than these candidate lists, and may need a shortlist first. Clef's results might improve with other question wording, which this trial did not tune.

## Reproduce

```bash
bun eval/system-one/run.ts --check    # RESULTS.md matches the recorded responses
bun eval/system-one/run.ts            # print the generated section
# Paid live calls; replaces recordings.json and the generated section:
BKPER_AI_BASE_URL=https://ai.bkper.app/v1 BKPER_AI_OAUTH_TOKEN=$(bkper auth token) bun eval/system-one/run.ts --live
```
