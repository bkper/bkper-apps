# Clairic extraction trial

Can Clairic, Cloudflare's System One extraction model (preview), read invoices and receipts as well as Extractor Bot does today? This trial extracts the same fields from the same synthetic documents with Clairic through the Bkper AI gateway's `POST /v1/systemone` (Open System One 2026-11-07) and with Extractor Bot's current path, Gemini Flash through `POST /v1/responses`. It changes nothing in Extractor Bot.

## Method

- 26 synthetic documents (`cases.ts`): 22 plain-text invoices, receipts and emails and 4 rendered images (`images/render.py`); 16 in English and 10 in Portuguese. Tags: receipt 12, invoice 11, missing_fields 9, email 7, number_format 6, image 4, messy 4, distractor_dates 3, yearless_date 2; a document can have several tags. Some fields are deliberately absent: date in 5 documents, total in 2, currency in 3, document number in 5.
- Six fields, the ones Extractor Bot records from an invoice or receipt: date, total, currency, supplier, document number and description. Each is correct, wrong, missed (null where the document states it), hallucinated (a value where it does not) or a correct null. Supplier and description are correct when they contain an accepted name or keyword, ignoring case and accents; document numbers are compared on letters and digits, without a leading `No`, `Nº` or `#`; currencies are normalized to ISO codes, reading a bare `$` as USD.
- Gemini: the bot's `ExtractorInvoice`, unchanged (system prompt, schema, `gemini-flash`, medium reasoning, retries), through `BkperAIResponsesClient` (`gemini.ts`). Books get properties by configuring a transaction prompt, which replaces the default user prompt; the trial's prompt is the default with its "no additional property" rule replaced by `supplier`, `document_number` and `currency`. The bot's schema requires an amount, so an amount of 0 counts as no total. Text documents go in as `text/plain` files and images as `image/png` or `image/jpeg`, as the bot sends them.
- Clairic: one request per document (`request.ts`) with `date`, `number` and `text` questions for the six fields, plus three `list` questions for item amounts, charges and discounts, and `reference_date` 2026-10-31 so year-less dates resolve. An image is an asset, and the state is `Scanned document: document-scan`, naming its placeholder. Clairic is never asked to add anything up: code checks that items plus charges minus discounts equal its total, in cents. Text spans are checked against the state (or `state_text`) in code points.
- 52 live calls (one per document and model, sequential, no retries needed) on the dev gateway on 2026-11-07, recorded in `recordings.json` without Gemini's encrypted reasoning blobs. Latency is wall time measured from the caller, including the network. Every request body was distinct, so the gateway's response cache was never hit. Cost is usage times the gateway catalog price at recording time, which includes Bkper's markup: Clairic 150 nano USD per input token and no output price; Gemini Flash 2,300 per input token and 11,000 per output token, reasoning included.

## Findings

- **Image documents failed on Clairic.** All four returned HTTP 502 `provider_invalid_answer`: the gateway rejected Clairic's `currency` answer for breaking the format guarantee (two documents) or the null rule (two documents), and Open System One fails the whole request when one answer breaks a guarantee. A manual probe outside the recording (one call: the grocery receipt image without the `currency` question) succeeded: date, total, document number and item amounts were correct, but the supplier was read as "GREENLE MARKET" and the description was "S" with a span into the placeholder text. A smoke call before the run, with the state `Scan: page-1`, answered the seller with the placeholder itself.
- **The reference date leaks into dates.** All 5 of Clairic's wrong or hallucinated dates are the request's `reference_date`: 3 documents with no date and 2 that state their date (the hotel folio and the order email). Gemini returned null on all 5 documents without a date. Gemini's three date misses are the bot's own rules: it leaves year-less dates null (the bot sends no reference date and its prompt forbids inferring one), and it read `10/11/26` on a US fuel receipt as day/month, as its prompt's DD/MM/YY rule says.
- **Clairic's guesses are often right where its values are null.** Currency is the clearest case: 6 of 23 stated currencies as values, but 17 of 23 as guesses. Clairic usually found the symbol (`$`, `R$`) and still put `p_null` above 0.5. A lower `null_threshold` might recover some of these at the cost of hallucinations; this trial did not test it.
- **Text answers are copies.** Clairic copies text from the state, so descriptions are the first item line ("Copy paper A4, box of 10") rather than a summary, and all three wrong suppliers were the customer or payer named in the document. Every text span covered exactly its guess (88 of 88), which is useful provenance; numbers, dates and list items came back without spans, so amounts and dates have no provenance.
- **Totals are Clairic's strongest field.** On the 22 text documents every total was right, both nulls included (the four total misses are the four failed image documents). For 12 documents, code verified the total from the items Clairic read, and every verified total was correct. The other 8 correct totals could not be verified: 2 documents list no items, and on 6 an item, charge or discount was missing or wrong, such as the freight on the NF-e or the VAT on the euro invoice.
- **Confidence does not close the gap.** Accepting only Clairic values with confidence at least 0.99 raises precision from 88.8% to 94.3% while keeping 35.5% of the stated fields; Gemini, without confidences, was right on 98.1% of all fields.
- **Clairic is much faster and cheaper.** Median latency 444 ms against 4,756 ms, and about 36 times cheaper per document ($0.000263 against $0.009485). Gemini's cost is mostly reasoning tokens: the fuel receipt alone used 8,891 output tokens and 65.8 s, about $0.099, 40% of Gemini's total.

## Recommendation

**Not yet: keep Gemini as Extractor Bot's extraction path.**

- Gemini was right on 98.1% of all fields (97.7% on text documents) and never hallucinated a value. Clairic was right on 62.2% (73.5% on text documents), failed every image document, and turned the reference date into 5 wrong dates.
- No single field is ready to move. Total is the only field Clairic matched Gemini on, and only on text documents (all correct); date, currency, supplier, document number and description trail Gemini by 23 to 65 points of field accuracy.
- A hybrid is the only plausible next step, and it needs separate approval: on text documents, run Clairic beside Gemini and compare Clairic's item-verified total with Gemini's amount. Agreement would be cheap extra evidence (about 3% of a Gemini extraction's cost) and Clairic's text spans could show where supplier and number came from. Measure it on real, consented documents before relying on it.
- Revisit when Clairic leaves preview, once image documents no longer break answer guarantees and dates no longer default to the reference date. A re-run is one command, and should also try without `reference_date` and with a lower currency `null_threshold`.

Limits: 26 synthetic documents written and labelled by one author, one run per model, and small counts. Field matching is lenient for supplier and description, which favours neither model's wording in particular but does reward Gemini's summaries over Clairic's copied lines. Gemini's properties came from a configured prompt written for this trial; Books without one get only date, amount and description. Clairic's question wording was not tuned.
